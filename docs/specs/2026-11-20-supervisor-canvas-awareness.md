# 总管画布感知

- **状态**：Draft（2026-11-20）
- **范围**：supervisor 候选卡、工具白名单与 prompt
- **关联**：`docs/specs/2026-11-18-m2-supervisor-design.md`

## 背景

总管目前只能看到“当前选中节点”和任务列表。用户在画布上新建文本/文件节点但未选中时，
问“画布有什么”，总管只能调用 `list_tasks`，然后回答“没有任务 / 没有选中节点”，
把任务列表当成了画布内容。画布是 baton 的共享内存，总管必须能看到画布摘要。

## 决定

- 候选卡始终附带 `<canvas_overview>`：节点总数、连线总数、最多 20 个节点的 `id/type/title`（Agent 带 engine），超出时标记 truncated。
- 新增只读工具 `list_canvas`：
  - 返回当前 workspace 画布的节点与连线摘要；节点最多 100 个（参数上限 200），连线最多 200 条。
  - 文本节点返回前 200 字预览；文件节点只返回名称/路径，不读文件内容；Agent 返回 title/engine/taskId；group 返回 label。
  - 只读，不创建、不修改、不读文件系统。
- prompt 从 7 个工具改为 8 个，并明确：
  - 用户问画布内容时先看 `<canvas_overview>`，需要细节调用 `list_canvas`；
  - 不得把任务列表当作画布内容，也不得在没查画布时说“不知道”。
- 仍然不读代码、日志、transcript 或文件内容；画布摘要只到文本预览。

## 后果

- 总管能回答“画布上有什么”，也能基于画布节点组织任务。
- 候选卡与工具输出都有上限，token 成本可控。
- 文件节点只暴露路径和名称，不泄露文件内容；文本节点只暴露 200 字预览。
- 引擎必须把 `BoundToolset` 的全部 8 个工具传给模型；单测断言请求体中的工具名，避免 prompt 宣传了工具但实际没接线。

## 验收

- 画布上有文本 + 文件节点、无选中时，问“画布有什么”，总管回复节点标题/类型，而不是“没有任务”。
- 候选卡包含 `<canvas_overview>`；`list_canvas` 返回节点与连线摘要并有 truncated 标记。
- 跨 workspace 不可见；现有 7 个工具行为不变。
