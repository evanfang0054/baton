# ADR 0007：移动端从只读改为响应式控制台

- 状态：Accepted
- 日期：2026-11-19
- 决策者：项目负责人
- 关联：架构 spec §1.3 / 决策 #16；M2-2a spec §15；M2-2b 移动端响应式控制台 spec

## 背景

架构 spec 原定 v1 移动端只读：手机看板 + 通过/打回，触控画布不做，理由是成本高、收益低。

M2-2a 完成后，M2 验收只剩“手机上能通过/打回”。实际使用中，只读会把手机变成通知窗口：审批、回复、开工、建任务仍然要把人拉回桌面，“离开电脑也能推进任务”的注意力回路没有闭合。

应用户要求，M2-2b 改为移动端响应式控制台：手机拥有除画布外的完整控制面。

## 决策

- `<768px`：移动控制台，完整非画布控制面；不挂载画布组件。
- `768–1023px`：压缩桌面，保留画布；看板默认收起，右栏改覆盖层。
- `≥1024px`：现有桌面布局不变。
- 手机端动作：看板、任务详情、审批/回复/验收、开工/取消/批量开工、建任务表单、总管聊天、自动化设置、workspace 切换/创建/信任、kill switch 暂停/恢复、digest/未读。
- 节点：创建/编辑 text/file；任务表单可新建 Agent；不删除节点、不建连线；不创建 image/group/review 节点。
- 认证沿用 `/auth?token=` HttpOnly cookie 与同一 token；不新增只读 token scope。
- 通知保持站内未读 + digest；不做 Web Push/外部渠道。
- 无 `packages/protocol`、`apps/daemon`、DB、migration 变更；复用现有 REST/WS 命令。

## 备选方案

- **保持移动端只读**：拒绝。不能闭合“离开电脑”的注意力回路，审批和开工仍被桌面绑死。
- **独立移动壳/路由**：拒绝。与现有三栏重复，维护两套布局；用户明确选择响应式改造现有壳。
- **触控画布**：拒绝。架构已判定成本高、收益低；手机不做画布，只保留节点选择与表单编辑。

## 后果

**正面**

- M2 验收闭合：手机可完成从查看、审批、回复、开工到验收的闭环。
- 桌面布局保持不变；平板保留画布，只做压缩布局。
- 无协议/DB 变更，复用已有命令和状态机。

**负面**

- 响应式改动面大，桌面组件存在回归风险。
- 手机 token 拥有完整权限；手机丢失等同于凭据泄露。
- 移动 bundle 仍包含 React Flow（先测量，后续再考虑懒加载）。
- 节点删除、连线和画布布局仍只能桌面完成。

**缓解**

- Playwright 覆盖手机/平板/桌面三档；桌面 e2e 全量回归。
- runbook 明确远程访问、token 轮换与截图脱敏；不在前端 localStorage 保存敏感信息。
- 先测量移动首屏与交互，再决定是否代码分割。
- 文档明确“手机是控制面，不是画布编辑器”。
