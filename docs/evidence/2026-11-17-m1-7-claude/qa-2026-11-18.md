# M1-7a ego-lite 真实验收记录

日期：2026-11-18
环境：本机 daemon + Vite dev，隔离数据目录与临时工作区；真实 Claude Code（OAuth）。

## 已走通的路径

1. 空状态 → 新建工作区 → trust 弹窗（取消 / 重新打开 / hooks 开关）→ 已信任徽标。
2. 新建 Agent 节点 → 引擎默认 Claude（`unknown` 状态与中文原因）→ 创建任务。
3. 真实 Claude 执行：生成文件 → `Write` 审批卡 → 允许 → verify 退出码 0 → 验收通过 → 已完成。
4. 刷新页面：workspace trust、任务状态、transcript、审批与验收记录均保留。
5. 运行中取消：任务进入已取消，SDK 子进程退出，无残留。
6. 模型提问 → `baton_report blocked` → 回复 → 同一会话继续执行。

## 发现并修复的问题

| 问题 | 影响 | 修复 |
|---|---|---|
| `canUseTool` 审批 resolve 前先 `pending.delete`，`finish()` 认为请求已失效 | 允许后 SDK 永久挂起，任务卡在 running | `approve` 不再预删除，交给 `finish` 删除；单测覆盖 ready 立即收尾 |
| `ready` 等 `turn_result` 才关闭 | resumed turn 不返回 result 时会挂死 | 收到 `ready` 立即发 `RUN_FINISHED` |
| `AskUserQuestion` 未禁用 | 弹出无法回答的结构化问题审批 | 加入 `DISALLOWED_TOOLS`，改用文本 + `baton_report blocked` |
| `waiting_input(stalled)` 仍显示回复框 | 用户无法回复一个已丢失的会话 | 停滞态改为「重新入队 / 取消任务」 |
| `waiting_input` 统一显示「待审核」 | 与 review 混淆 | 改为「待处理」 |
| Agent 节点固定显示 `fake` | 与任务实际引擎不一致 | 显示任务引擎或「未创建任务」 |
| 引擎原因英文 | UI 文案不统一 | web 侧本地化 |
| `task.status` 重连丢失后列表不刷新 | 状态/看板不更新 | 关键 `session.event` 也触发任务失效；WS 重连后刷新 workspaces/canvas/tasks |
| 会话状态英文 | UI 文案不统一 | 本地化 running/waiting_input/ended/failed |
| 非 git 工作区 diff 为 0 无解释 | 验收卡误导 | 标注「Git 文件」，tooltip 说明统计口径 |

## 残余限制

- `Bash` 的安全命令可能由 SDK 内置分类器直接放行，不经过 `canUseTool`；baton policy 只能在 SDK 询问时裁决。
- 非 git 工作区无法统计未跟踪文件行数；验收仍以 verify 退出码为主。
- 模型偶尔不调用 `baton_report` 而以纯文本提问；按设计会收敛为 `waiting_input(stalled)`，需要重新入队。
